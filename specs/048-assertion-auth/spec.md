# Feature Specification: 断言增强与自动补用例鉴权

**Feature Branch**: `048-assertion-auth`
**Created**: 2026-11-04
**Status**: Draft
**Input**: User description: "断言增强与自动补用例鉴权：接口用例生成时基于 2xx 响应 schema 追加 jsonschema 断言、状态码改为 2xx 范围；自动补用例时若接口需要鉴权，生成「登录 → 调用」两步用例并注入 token，登录接口查找复用统一规则。"

## 背景

047 的真机验证暴露两个问题：

1. 规则/自动生成的接口用例只断言「状态码 200」——接口返回 200 但字段缺失、类型错误、业务码异常都会被判为通过（假绿）。
2. 需要登录的接口，自动补出的用例没有登录步骤，执行必然 401，自动化闭环在鉴权处断裂。

本特性不新增业务功能，而是提升「自动生成的用例是否测得准、跑得通」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自动用例能发现结构错误（Priority: P1）

接口定义带有 2xx 响应结构时，平台生成的用例会校验整个响应体（必填字段、类型），而不是只看状态码。

**Why this priority**: 假绿比没有用例更危险；这是自动用例可信度的地基。

**Independent Test**: 对带响应 schema 的接口生成用例，检查断言包含「状态码 2xx 范围」与「响应符合 JSON Schema」；用一个字段缺失的响应执行，应判定失败。

**Acceptance Scenarios**:

1. **Given** 接口定义包含 2xx 响应 schema，**When** 生成用例，**Then** 正向用例至少包含状态码范围断言与响应结构断言。
2. **Given** 接口实际返回 200 但缺少 schema 中的必填字段，**When** 执行用例，**Then** 判定失败并指出缺失字段路径。
3. **Given** 接口没有响应 schema，**When** 生成用例，**Then** 保持原有断言（状态码范围 + 可选字段存在），不额外报错。
4. **Given** 负向用例（缺参/类型错误/鉴权失败），**When** 生成，**Then** 仍期望 4xx，行为不变。

---

### User Story 2 - 需登录接口的自动用例能跑通（Priority: P2）

自动补用例时，如果接口需要鉴权且项目里存在登录接口定义，用例会自动带上「登录 → 调用」两步，并注入登录得到的凭证。

**Why this priority**: 鉴权是自动用例红掉的头号原因；补上后 047 的闭环才真正可用。

**Independent Test**: 项目内有登录接口定义与一个需鉴权接口，触发自动补用例；检查用例为两步、第一步为登录、第二步请求带鉴权头；执行应通过（登录成功时）。

**Acceptance Scenarios**:

1. **Given** 接口声明了鉴权要求且项目存在登录接口定义，**When** 自动补用例，**Then** 生成两步用例：先登录，再调用目标接口并携带凭证。
2. **Given** 接口声明了鉴权要求但项目没有登录接口定义，**When** 自动补用例，**Then** 只生成调用步骤，并在用例说明中提示需提供凭证。
3. **Given** 登录接口查找，**When** 人工生成与自动补用例分别执行，**Then** 使用同一套判定规则，结果一致。

### Edge Cases

- 登录接口自身声明了鉴权要求：不应被选为登录接口。
- 登录响应通过 Cookie 而非响应体返回凭证：本期按现有生成器能力处理，记为已知限制。
- 接口响应不是 JSON 却有 2xx schema：结构断言失败即为正确反馈（schema 声明与实现不符）。
- 响应 schema 为空对象或缺失：不生成结构断言。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 当接口定义包含 2xx 响应 schema 时，生成的正向用例 MUST 包含校验整个响应体的结构断言（字段存在性与类型）。
- **FR-002**: 正向用例的状态码断言 MUST 表达为 2xx 范围（≥200 且 <300），不再绑定单一状态码。
- **FR-003**: 无响应 schema 时 MUST 保持原有断言能力，不得因缺少 schema 而失败或减少断言。
- **FR-004**: 负向用例（缺参、类型错误、鉴权失败）MUST 继续期望 4xx，不得被本次调整影响。
- **FR-005**: 自动补用例时，若接口声明了鉴权要求且项目内存在登录接口定义，MUST 生成「登录 → 调用」两步用例，并把登录凭证注入调用请求。
- **FR-006**: 找不到登录接口定义时 MUST 生成单步用例并在说明中提示需要提供凭证，不得静默生成必然失败的用例。
- **FR-007**: 人工生成与自动补用例 MUST 使用同一套登录接口判定规则（方法、路径特征、是否自身需要鉴权）。

### Key Entities

- **接口定义**：包含请求方法与路径、请求结构、2xx 响应结构、鉴权声明。
- **接口用例**：包含一个或多个步骤；步骤含请求、断言、提取器；自动补的用例带 `[自动]` 标识。
- **登录接口定义**：用于获取凭证的接口（通常为 POST、包含账号口令字段）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 带 2xx 响应结构的接口，生成用例的断言数量 ≥2，且其中包含结构校验。
- **SC-002**: 用「字段缺失」的响应执行结构断言用例，100% 判定失败（假绿可被识别）。
- **SC-003**: 存在登录接口定义时，需鉴权接口的自动用例 100% 为两步且携带凭证；无登录定义时 100% 在说明中提示。
- **SC-004**: 现有生成与执行行为无回归（全量单元测试通过）。

## Assumptions

- 登录凭证可从登录响应体提取（现有生成器能力）；Cookie 型登录不在本期范围。
- 响应结构断言依赖接口定义中的响应 schema（通常来自 OpenAPI）；源码提取的接口多数没有响应 schema，此时退回原有断言。
- 自动补用例的鉴权查找在项目范围内进行，最多扫描 500 个接口定义。
