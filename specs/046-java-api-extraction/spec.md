# Feature Specification: Java 接口自动提取与变更触发

**Feature Branch**: `046-java-api-extraction`  
**Created**: 2026-10-30  
**Status**: Draft  
**Input**: User description: "从平台直接拉取 Java 项目 Git 仓库，自动提取接口定义并生成用例；仓库有变更后，执行变动部分的接口用例。部分项目有 OpenAPI，部分没有，需要兼容".

## Clarifications

### Session 2026-10-30

- Q: 接口同步怎么触发？ → A: 手动 + 定时（平台按配置周期自动同步）
- Q: 代码变更后找到受影响用例，接下来怎么做？ → A: 先列出受影响清单与待执行计划；**1 小时内人工未确认则自动执行**；人工可提前确认或取消

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从代码仓库自动获得接口清单 (Priority: P1)

测试工程师在平台里为一个 Java 项目绑定代码仓库（地址 + 只读凭据 + 分支）。平台拉取代码后，自动识别项目用的是什么技术栈（有没有 OpenAPI、用的什么框架），并产出一份接口清单：每个接口的请求方法、路径、参数与来源位置（文件 + 行号）。工程师不需要手工维护接口定义。

**Why this priority**: 这是整个能力的地基。没有可靠的接口清单，"变更触发用例"无从谈起。

**Independent Test**: 对一个有 OpenAPI 的项目和一个没有 OpenAPI 的 Spring 项目各绑定一次仓库，都能得到接口清单；清单里的路径与浏览器/接口工具里实际调用的路径一致。

**Acceptance Scenarios**:

1. **Given** 项目提供 OpenAPI 文档地址，**When** 绑定仓库并同步，**Then** 接口清单来自 OpenAPI，路径与参数 schema 完整。
2. **Given** 项目没有 OpenAPI 但使用 Spring 注解声明接口，**When** 同步，**Then** 平台解析源码得到接口清单，并给出「类级 + 方法级」拼接后的完整路径。
3. **Given** 项目既没有 OpenAPI、注解也解析不出路径（如路径由运行时拼接），**When** 同步，**Then** 明确提示该接口或该模块"无法确定路径"，不编造路径。
4. **Given** 同一个项目重复同步，**When** 第二次同步，**Then** 已存在的接口不重复创建，只更新有变化的字段。

---

### User Story 2 - 接口清单随代码自动更新 (Priority: P2)

开发提交新接口或修改接口参数后，工程师希望平台的接口定义跟着更新，而不是每次手工重新导入，也不必每次全量重建。

**Why this priority**: 自动化只有"持续自动"才有价值；一次性的导入仍会腐化。

**Independent Test**: 在仓库里新增一个接口并提交，触发同步后平台新增该接口；删除一个接口后同步，平台将其标记为已下线而非直接删除。

**Acceptance Scenarios**:

1. **Given** 仓库新增了接口，**When** 同步，**Then** 平台新增该接口定义。
2. **Given** 仓库删除了接口，**When** 同步，**Then** 平台标记该接口已下线，保留其历史与关联用例。
3. **Given** 仓库只改了接口的参数或描述，**When** 同步，**Then** 更新接口定义，并记录变更点。

---

### User Story 3 - 代码变更后只跑受影响的接口用例 (Priority: P2)

开发提交了代码，工程师希望平台自动找出这批改动影响了哪些接口、这些接口有哪些用例，并只跑这些用例，而不是全量回归。

**Why this priority**: 这是本需求的核心收益：用最小执行量覆盖本次变更。

**Independent Test**: 修改一个 Controller 的某个接口，触发变更检查，平台列出受影响的接口与用例，执行后给出结果；不相关的用例不执行。

**Acceptance Scenarios**:

1. **Given** 仓库有新提交改动了若干 Java 文件，**When** 变更检查执行，**Then** 平台输出「变更文件 → 受影响接口 → 关联用例」的清单，并生成一份**待确认**的回归计划。
2. **Given** 待确认计划生成后 1 小时内无人操作，**When** 倒计时结束，**Then** 系统自动执行该计划，并记录「超时自动执行」。
3. **Given** 待确认计划生成后 1 小时内有人确认，**When** 点击确认，**Then** 立即执行，不再等待超时。
4. **Given** 待确认计划生成后 1 小时内有人取消，**When** 点击取消，**Then** 不执行该计划，并记录取消原因与操作人。
5. **Given** 受影响接口中部分有自动化用例，**When** 计划执行，**Then** 只执行这些用例，并生成可追溯的执行批次。
6. **Given** 某次提交只改了注释或没有命中任何接口，**When** 变更检查执行，**Then** 明确提示「本次变更未影响接口」，不创建计划、不启动倒计时。
7. **Given** 同一批改动被重复触发（如连续提交），**When** 变更检查执行，**Then** 合并到同一份待确认计划，不重复创建、不重置已过时间以外的重复倒计时。

---

### User Story 4 - 来源可追溯与可信度可见 (Priority: P3)

工程师在接口详情里能看到这个接口是从哪来的（OpenAPI / 源码第几行 / 手工），以及自动提取的可信程度，对低可信度的接口可以选择手工修正。

**Why this priority**: 自动提取不可能 100% 准确，可追溯与可修正决定了长期可用性。

**Independent Test**: 打开一个源码解析得到的接口，能看到来源文件与行号；打开一个路径含运行时拼接的接口，能看到"低可信度"提示。

**Acceptance Scenarios**:

1. **Given** 接口来自源码解析，**When** 查看详情，**Then** 显示来源文件、行号与提取方式。
2. **Given** 接口路径无法完全确定，**When** 查看详情，**Then** 标记为低可信度并说明原因。
3. **Given** 工程师手工修正了接口路径，**When** 再次同步，**Then** 手工修正不被自动同步覆盖。

---

### Edge Cases

- 仓库存在多个模块（多模块 Maven/Gradle），接口分散在不同子模块。
- 同一个路径在不同版本（分支）上不同，平台只关注配置的那个分支。
- 仓库很大（十万级文件），首次同步耗时长；必须能中断与续跑。
- 仓库需要认证：只读凭据失效时，同步失败必须给出明确原因，而不是产生空清单。
- 接口路径由配置中心或环境变量决定（如 `${api.prefix}`），源码里拿不到最终值。
- 项目同时存在 OpenAPI 与源码，且两者不一致（OpenAPI 未更新）：以 OpenAPI 为准，但记录差异。
- 一个 Controller 文件里包含多个接口，文件级变更会命中多个接口（允许误报，不允许漏报）。
- 变更触发时，目标环境不可用：应记录失败原因，不阻塞后续触发。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 平台 MUST 支持为项目绑定代码仓库（地址、分支、只读凭据），凭据加密存储且不在界面回显。
- **FR-002**: 平台 MUST 在同步前自动识别项目的接口暴露方式（是否提供 OpenAPI、使用何种类声明方式），并选择对应的提取方式。
- **FR-003**: 当项目提供 OpenAPI 时，平台 MUST 优先以 OpenAPI 作为接口来源。
- **FR-004**: 当项目不提供 OpenAPI 时，平台 MUST 能从 Java 源码解析出接口的请求方法、路径与来源位置（文件、行号）。
- **FR-005**: 路径解析 MUST 合并类级与方法级路径声明，并解析字面量常量拼接；无法确定时必须标记低可信度并保留原始表达式。
- **FR-006**: 平台 MUST 为每个接口记录来源（提取方式、文件、行号）与可信度。
- **FR-007**: 同步 MUST 幂等：同一接口重复同步不重复创建，只更新变化字段。
- **FR-008**: 仓库中消失的接口 MUST 被标记为下线，而不是删除，历史与关联用例保留。
- **FR-009**: 工程师 MUST 能手工修正接口信息，且修正内容在后续同步中不被覆盖。
- **FR-010**: 平台 MUST 支持手动触发同步与按计划自动同步。
- **FR-011**: 平台 MUST 能比较两个提交之间的代码差异，输出受影响的接口清单。
- **FR-012**: 平台 MUST 能把受影响接口映射到已有自动化用例，并生成一份**待确认**的回归计划。
- **FR-013**: 待确认计划 MUST 有 1 小时确认窗口：窗口内人工确认则立即执行，取消则不执行，超时未处理则自动执行；三种结局都 MUST 留痕（操作人/时间/原因）。
- **FR-014**: 变更检查 MUST 合并重复触发：同一批改动只生成一份待确认计划，不重复创建。
- **FR-015**: 首次同步与增量同步 MUST 可中断、可续跑，且大仓库下不阻塞其他功能。
- **FR-016**: 同步失败（凭据失效、网络、解析异常）MUST 给出可行动的错误说明，不得静默产生空清单。
- **FR-017**: 平台 MUST 为每次同步与每次变更检查保留可查询的记录（时间、结果、影响范围、执行结局）。
- **FR-018**: 本特性 MUST NOT 改变现有接口用例的生成与执行能力；新提取的接口复用现有生成管线。

### Key Entities

- **代码仓库绑定**：项目与仓库的关联，含地址、分支、凭据、同步状态。
- **接口定义**：请求方法、路径、参数、来源位置、提取方式、可信度、状态（在用/下线）。
- **同步记录**：一次同步的时间、范围、新增/更新/下线数量、错误。
- **变更影响**：一次提交范围内受影响的接口集合，及其关联用例。
- **变更触发记录**：触发时间、提交范围、生成的执行批次、合并情况。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对提供 OpenAPI 的项目，接口清单覆盖率不低于 95%，参数完整率不低于 90%。
- **SC-002**: 对不提供 OpenAPI 的 Spring 项目，接口覆盖率不低于 80%，路径准确率不低于 90%（以实际调用路径为准）。
- **SC-003**: 首次同步一个万级文件仓库在 10 分钟内完成；增量同步（仅变更文件）在 1 分钟内完成。
- **SC-004**: 变更检查从提交到产出受影响清单不超过 2 分钟。
- **SC-005**: 变更触发执行时，漏报率（受影响的接口未被识别）不高于 5%；误报可接受但需可见。
- **SC-006**: 重复同步/重复触发不产生重复接口或重复执行批次（100%）。
- **SC-007**: 凭据失效、解析失败等异常场景，100% 给出可理解的原因。
- **SC-008**: 手工修正的接口信息在后续同步中 100% 保留。
- **SC-009**: 变更计划的确认窗口（默认 1 小时）到点自动执行的准点率 100%（误差不超过 1 分钟）；人工确认后立即执行，人工取消后 100% 不执行。

## Assumptions

- 目标 Java 项目使用 Git 管理，平台可通过 HTTPS + 只读凭据拉取。
- 项目以 Spring 系（MVC / Boot）为主；其他框架先按"无法自动提取"处理，后续扩展。
- 平台只关注项目配置的单一分支，不处理多分支对比。
- 接口清单用于生成用例与变更影响分析，不替代 OpenAPI 文档本身。
- 变更触发先产出影响清单与待确认计划；确认窗口默认 1 小时，可由项目配置调整；窗口内无人处理则自动执行。
- 不引入新的执行体系；执行复用现有批次与回归计划能力。
- 本期不做 UI 用例的代码变更映射（后续独立特性）。

## 增量规格 v2（2026-11-02）

> 依据首轮实现与真实验证结果，补齐 FR-009 / FR-013 / FR-015 的落地缺口，并补齐规模、体验与文档。

### 新增功能需求

- **FR-019（人工接管）**: 工程师 MUST 能在接口详情把接口标记为「人工修正」，也可取消该标记；带标记的接口在后续同步中 MUST NOT 被自动覆盖，也不得被自动下线。
- **FR-020（项目级确认窗口）**: 每个项目 MUST 能覆盖全局确认窗口（5–1440 分钟），未配置时继承全局默认 60 分钟；变更计划创建时使用项目配置。
- **FR-021（审计留痕）**: 手动/定时同步、计划确认/取消/超时自动执行 MUST 写入项目审计日志，包含操作人、动作、结果与受影响用例数。
- **FR-022（同步状态与中断）**: 同步开始时 MUST 立即落库 `running` 记录；MUST 提供取消接口；取消后记录 `cancelled` 并保留已完成的接口变更（同步幂等）。
- **FR-023（增量提取）**: 已同步过的仓库再次同步时，MUST 只解析变更文件对应的接口；首次同步全量；MUST 支持定期全量校准（按配置的 N 次增量后执行一次全量）。
- **FR-024（大规模仓库）**: 扫描 MUST 排除生成目录与依赖目录；文件数上限 MUST 可配置；超限时 MUST 在同步记录中给出明确提示，不得静默截断。
- **FR-025（手动检查变更）**: 手动同步完成后 MUST 能立即执行一次变更检查并生成待确认计划，无需等待定时巡检。
- **FR-026（体验闭环）**: MUST 支持解绑仓库、从变更计划跳转到执行批次；同步记录与变更计划列表 MUST 支持按状态筛选；计划生成与超时自动执行 MUST 产生站内通知。

### 新增验收标准

- **SC-010**: 标记人工修正的接口，在后续 3 次同步中字段保持不变（100%）。
- **SC-011**: 项目级窗口配置后，新建计划的倒计时与配置一致（±1 分钟）。
- **SC-012**: 每次同步与每次计划决策都能在审计日志中检索到。
- **SC-013**: 万级文件仓库的增量同步（仅变更文件）在 1 分钟内完成。
- **SC-014**: 手动「同步并检查变更」从点击到产出计划不超过 2 分钟（中型仓库）。
