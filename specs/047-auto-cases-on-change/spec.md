# Feature Specification: 变更即补用例（047）

**Feature Branch**: `046-java-api-extraction`（延续 046 分支，未单独开分支）
**Created**: 2026-11-03
**Status**: Draft
**Input**: 用户反馈"自动化测试还是不够，人的参与度还是太高"——选择优先补「变更即补用例」闭环。

## 问题

046 的变更触发只会映射**已有**用例：受影响接口如果没有任何用例，整批变更会返回 `no_affected`，既不建计划也不执行。结果是：

- 新接口上线后，没人写用例 → 永远不会被回归
- 代码变更后，受影响的新接口被静默跳过 → 自动化覆盖率不随开发增长
- 工程师仍需手工判断"这次改动的接口有没有用例、要不要补"

## Clarifications

- Q: 自动生成的用例是否要人工审核后再导入？ → A: **直接导入**（低风险），用例名带 `[自动]` 前缀并在 `api_spec.meta.auto_generated=true` 标记，人工可随时删除/修改。
- Q: 生成方式用规则还是 LLM？ → A: **规则生成优先**（纯函数、无外部依赖、可预测）；LLM 增强作为可选配置，默认关闭。
- Q: 同一接口每次变更都生成吗？ → A: 否。每个接口只自动生成一次（记录 `auto_case_generated_at`），人工删除后不重复生成，避免打扰。

## User Stories

### US1 - 变更后自动补齐缺失用例（P1）

开发提交了一个新接口或改了没有用例的接口，平台在变更检查时自动生成基础用例，并直接纳入本次回归计划执行。

**独立测试**：仓库中新增一个接口（无关联用例），触发同步与变更检查 → 生成 1~3 条 `[自动]` 用例 → 计划包含该接口与用例 → 确认/超时执行后产出批次。

**验收场景**

1. **Given** 变更命中接口 A（已有用例）和接口 B（无用例），**When** 变更检查，**Then** A 使用既有用例、B 自动生成用例，两者都进入同一计划。
2. **Given** 自动生成成功，**When** 查看接口定义，**Then** 能看到 `[自动]` 用例与接口关联，计划展开显示受影响接口与用例数。
3. **Given** 同一接口再次变更，**When** 变更检查，**Then** 不再重复生成（沿用上次自动用例）。
4. **Given** 自动生成抛错或规则无法生成，**When** 变更检查，**Then** 计划仍正常创建（只包含已有用例接口），错误写入计划说明，不阻塞同步。

### US2 - 可控与可追溯（P2）

团队可以开关该能力、限制单次生成规模，并追溯哪些用例是自动补的。

**验收场景**

1. **Given** 关闭 `api_auto_case_enabled`，**When** 变更检查，**Then** 行为回到 046 现状（无用例接口跳过）。
2. **Given** 单次变更命中 20 个无用例接口，**When** 生成，**Then** 最多处理配置的上限（默认 5 个接口），其余在计划说明中列出。
3. **Given** 自动生成了一批用例，**When** 查看审计，**Then** 能查到生成数量、接口清单与触发的变更计划。

## Requirements

- **FR-001**: 变更影响计算后，对没有任何用例的受影响接口，MUST 自动生成基础用例并导入为 `case_kind='api'` 的用例。
- **FR-002**: 自动生成的用例 MUST 可识别：名称前缀 `[自动]`，`api_spec.meta.auto_generated=true`，并记录来源定义与生成时间。
- **FR-003**: 自动补齐后 MUST 重新计算受影响清单，把新用例纳入本次变更计划。
- **FR-004**: 同一接口 MUST 只自动生成一次（`api_definitions.auto_case_generated_at`），人工删除后不重复生成。
- **FR-005**: 自动生成 MUST 受配置约束：总开关、单次最多接口数（默认 5）、单接口最多用例数（默认 3）、单项目每日上限（默认 50）。
- **FR-006**: 自动生成失败 MUST 不阻塞同步与计划创建；错误写入计划说明与同步记录。
- **FR-007**: 自动生成 MUST 写审计日志（项目、接口数、用例数、触发的计划）。
- **FR-008**: 该能力 MUST NOT 修改或删除人工创建的用例。

## Edge Cases

- 接口 `request_schema` 为空（OpenAPI/源码没解析出参数）：规则生成仍产出 1 条正常用例。
- 接口是 multipart/文件上传：默认跳过生成，计划说明中标注。
- 生成过程中数据库约束失败（重名等）：跳过该条，继续其他接口。
- 变更同时命中人工修正（`manual_override`）的接口：仍可自动补用例，但接口本身不被同步覆盖。

## Success Criteria

- **SC-001**: 无用例接口在变更后进入回归计划的比率 ≥ 90%（受上限约束的部分除外）。
- **SC-002**: 自动生成不产生重复用例（同一接口重复变更 3 次，用例数不增长）。
- **SC-003**: 变更检查总耗时增加不超过 3 秒（规则生成，每接口 ≤ 50ms，上限 5 个接口）。
- **SC-004**: 关闭开关后，046 现有行为 100% 保持。
