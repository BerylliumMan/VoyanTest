# Quickstart: 变更即补用例（047）

## 行为

当代码变更命中接口、但该接口没有任何用例时，平台会：

1. 用规则生成器补 1–3 条基础用例（正常流 + 必填缺失 + 边界）
2. 名称前缀 `[自动]`，`api_spec.meta.auto_generated=true`
3. 直接入库并纳入本次变更计划（不再 `no_affected` 跳过）
4. 计划执行时与人工用例一起跑

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `api_auto_case_enabled` | true | 总开关；关闭后回到 046 行为 |
| `api_auto_case_max_definitions` | 5 | 单次变更最多补几个接口 |
| `api_auto_case_max_each` | 3 | 单接口最多生成几条 |
| `api_auto_case_daily_limit` | 50 | 单项目每日生成上限 |

## 规则

- **每个接口只补一次**：`api_definitions.auto_case_generated_at` 非空后不再自动生成；人工删除后也不会重复生成。
- **只新增**：不修改、不删除人工创建的用例。
- **失败隔离**：生成或写入失败只记入计划说明，不阻塞同步与计划。
- **multipart/文件上传**：默认跳过（规则生成不准备文件）。
- **可识别**：用例列表可按名称 `[自动]` 检索，`api_spec.meta` 含来源定义、生成时间、触发计划。

## 验证方式

1. 绑定仓库并完成首次同步（建立基线）
2. 提交一个**没有用例**的新接口
3. 点「同步并检查变更」
4. 打开「变更计划」：受影响接口与用例数应 ≥ 1，计划可确认或超时自动执行
5. 接口用例列表可见 `[自动] xxx - 正常流`

## 注意

自动用例的请求 URL/参数来自接口定义（`{{baseUrl}}` + 路径），
执行前需确保项目/环境已配置正确的 `baseUrl`；否则用例会按失败记录。
失败不影响用例保留，可人工修正后继续使用。
